# Product Context

이 문서는 제품의 구현 방법보다 제품이 왜 존재하는지,
어떤 문제를 해결하려는지, 어떤 방향을 중요하게 생각하는지를 기록한다.

AI는 이 문서를 단순한 참고 자료가 아니라
설계와 구현 판단을 위한 제품 맥락으로 사용한다.

대화 과정에서 제품에 대한 새로운 결정이나 통찰이 생기면
기존 내용을 무작정 덧붙이지 말고,
현재 제품 방향을 가장 잘 설명하도록 이 문서를 갱신한다.

기술 스택, 클래스 구조, API 상세처럼 코드나 기술 문서에서
충분히 확인 가능한 정보보다,
코드만으로는 복원하기 어려운 제품 의도와 결정 이유를 우선해서 기록한다.


## Why

모아쓰기는 회의에서 각자의 생각을 모으고, 서로의 반응을 확인한 뒤,
진행자가 하나의 아이디어를 선택할 수 있도록 돕는 도구다.

참가자는 남의 아이디어를 보기 전에 자신의 생각을 작성하고,
작성자를 드러내지 않은 상태에서 서로 평가한다.
선택할 때에는 단일 점수나 순위 대신 평가 분포를 참고한다.
독립적으로 생각할 기회와 서로의 의견을 살펴볼 근거를 제공하는 것이 핵심 가치다.


## Problem

대상은 하나의 안건에 대해 아이디어를 내고 선택해야 하는 회의의 진행자와 참가자다.
현재 제품이 다루려는 문제는 다음과 같다.

- 다른 사람의 생각을 먼저 보면 각자의 생각을 독립적으로 작성하기 어려울 수 있다.
- 작성자가 누구인지 알면 아이디어 자체에 대한 평가에 영향을 줄 수 있다.
- 점수나 순위 하나로 요약하면 의견이 고르게 모였는지, 엇갈렸는지 파악하기 어렵다.
- 회의에 참여하기 위해 계정을 만들어야 한다면 핵심 행동까지의 절차가 늘어난다.

이 문제들은 현재 제품 방향에서 읽을 수 있는 문제 가설이다.
제품을 만들게 된 구체적인 경험, 기존 회의 방식의 불편, 사용자 조사 결과는
아직 기록되어 있지 않으므로 확인된 사실로 단정하지 않는다.


## Insight

현재 설계는 생각을 내는 과정과 서로 평가하는 과정을 분리하고,
평가가 끝난 뒤에 결과를 함께 보는 접근을 택한다.
작성 중 다른 아이디어를 숨기고 평가 중 작성자와 중간 집계를 숨기는 것은
각자의 생각과 판단을 보호하려는 방향에 맞는다.

평가 분포는 선택의 참고 자료이며 선택 자체를 대신하지 않는다.
이 접근이 실제 회의에서 어떤 효과를 내는지는 아직 검증 결과가 기록되어 있지 않다.


## Product Direction

진행자가 안건을 만들고 QR이나 링크로 공유하면,
참가자는 계정 없이 닉네임으로 들어와 자신의 생각을 작성할 수 있어야 한다.
진행자는 참가자이기도 하며 회의 상황에 맞춰 작성 → 평가 → 결과로 수동 전환한다.

참가자는 자신의 아이디어를 명시적으로 저장·수정하고,
평가 단계에서는 다른 사람의 익명 아이디어에 대한 반응을 선택·변경한다.
결과에서는 아이디어별 평가 분포를 확인하고 진행자가 하나를 채택한다.
제품은 자동으로 승자를 결정하기보다 사람의 선택을 돕는다.

### 현재 합의된 범위

- 비로그인 생성·참가를 지원한다. 신규 참가는 작성 중에만 허용하고, 같은 안건 내 닉네임 중복은 금지한다. 닉네임은 앞뒤 공백을 제거하고 대소문자를 구분하며 내부 공백은 유지한다.
- 참가자당 아이디어는 하나다. 명시적인 저장·수정만 제공하고 삭제는 제공하지 않는다. 작성 중에는 다른 참가자의 아이디어를 숨긴다.
- 평가는 좋음/괜찮음/별로를 선택하면 항목별로 저장되며 변경할 수 있다. 자기 아이디어 평가와 중간 집계 공개는 없다.
- 결과는 평가 분포로 표시하며 점수·순위는 없다. 진행자는 결과에서 한 번 채택하고 변경하지 않는다. 채택작 작성자만 공개한다.
- 아이디어가 없으면 작성 화면에서 안내하고 평가 시작을 거부한다. 평가가 없는 아이디어도 결과에 표시하고 채택할 수 있으며, 해당 항목은 평가 없음으로 표시하고 분포를 생략한다.
- QR·공유 링크·참가자 목록·단계 전환 관리 영역을 제공한다. 작성·평가 완료 인원 집계는 제공하지 않는다.
- 로그인·JWT·참가 키 만료·키 복구는 현재 범위 밖이다. 향후에도 비로그인 참가는 지원한다.

향후 비로그인 진행 허용 여부, 홈·관리 영역의 배치,
화면 갱신 간격은 아직 정하지 않았다. 해당 기능을 다룰 때 확인한다.
상세 흐름과 구현 순서는 `docs/moasseugi-overview.md`,
API·DB·화면 계약은 각 기술 설계 문서에서 관리한다.


## Principles

- 각자 먼저 생각할 수 있어야 한다. 작성 단계에서 다른 사람의 아이디어를 공개하는 선택은 이 원칙을 기준으로 판단한다.
- 평가자는 아이디어 자체를 판단할 수 있어야 한다. 평가 중 작성자나 중간 집계를 드러내지 않는다.
- 서로의 반응이 어떻게 나뉘는지 보여준다. 평가 분포를 단일 점수·순위로 대체하지 않는다.
- 회의의 진행과 최종 선택은 진행자가 맡는다. 단계는 수동으로 전환하고 채택도 진행자가 결정한다.
- 계정 없이도 참가할 수 있어야 한다. 향후 로그인 도입이 비로그인 참가를 없애는 근거가 되어서는 안 된다.
- 독립 작성 → 익명 평가 → 선택이라는 핵심 흐름을 우선한다. 기능 확대나 미정 규칙의 확정은 이 흐름에 필요한지 확인한다.


## Not the Goal

현재 제품은 점수·순위로 승자를 정하는 경쟁 도구나,
회의의 상황과 무관하게 자동으로 마감하는 도구를 목표로 하지 않는다.

자동 마감·시간 연장·스케줄러·카운트다운·단계 되돌리기,
여러 아이디어 제출·삭제, 로그인 계정 연결·과거 기록 병합은 현재 범위 밖이다.
현재 제외된 기능 전체를 영구 금지로 해석하지 않는다.
향후 범위를 바꿀 때에도 위 목적과 원칙에 맞는지 확인하고 결정을 기록한다.
