# 모아쓰기

## 핵심 가치

각자 남의 아이디어를 보지 않고 생각을 작성하고, 익명으로 서로 평가한 뒤 평가 분포를 참고해 하나를 선택하는 회의 도구다.

## 핵심 흐름

1. 진행자가 안건 제목·설명과 닉네임으로 안건을 만든다. 생성자는 참가자이기도 하다.
2. QR·링크를 공유하고 참가자가 닉네임으로 들어온다. 같은 안건의 닉네임은 중복되지 않아야 한다.
3. 참가자마다 아이디어 하나를 작성·저장·수정한다. 다른 사람의 아이디어는 작성 중 보이지 않는다. 삭제는 없다.
4. 진행자가 평가를 시작한다. 아이디어가 없으면 “등록된 아이디어가 없습니다”를 표시하고 전환을 거부한다.
5. 본인 것을 제외한 익명 아이디어에 좋음/괜찮음/별로를 선택한다. 클릭할 때 저장하며 변경할 수 있다. 중간 집계는 보이지 않는다.
6. 진행자가 평가를 종료해 결과로 전환한다. 점수·순위 대신 아이디어별 평가 분포를 표시한다. 평가가 없는 아이디어는 “평가 없음”을 표시하고 분포는 생략한다.
7. 진행자가 하나를 채택한다. 결과 단계 그대로 채택값을 기록하며 한 번 채택하면 변경하지 않는다. 채택작 작성자만 공개한다.

## 식별과 접근

계정 없이 안건별 랜덤 참가 키를 발급하고 브라우저에 보관한다. 서버는 키로 현재 참가자를 찾고 진행자인지 확인한다. URL의 admin 플래그는 권한으로 사용하지 않는다.

신규 참가는 작성 중에만 허용한다. 이후에는 기존 참가자가 이어서 참여한다. 키 만료·복구는 없다. 키를 잃으면 작성 중 새 닉네임으로 다시 참가할 수 있지만 기록을 이전하지 않는다. 진행자 키를 잃으면 관리할 수 없다.

결과의 공개 조회와 채택작 작성자만 공개하는 규칙은 기존 설계를 유지한다. 로그인은 추후 추가하고 비로그인 참가 방식은 유지한다. 향후 비로그인 진행 허용 여부는 아직 정하지 않았다. 로그인 계정 연결·과거 기록 병합은 지금 만들지 않는다.

## 남길 것과 제외할 것

남김: QR·링크, 진행자 관리 영역, 참가자 목록, 단계 전환, 작성·익명 평가·분포·채택, 최소 오류 응답.

제외: 회원가입·로그인·JWT, 자동 마감·시간 연장·스케줄러·카운트다운, 완료 인원 집계, 여러 아이디어·삭제, 별도 공통 기반 개발, 세부 오류코드 체계, 코드 생성.

홈·관리 영역의 배치, 닉네임 비교 방식, 화면 갱신 간격은 해당 기능 구현 때 확인한다. 불필요한 안내·오류 전용 화면을 먼저 만들지 않고 필요한 문구를 현재 화면에서 표시하는 안을 따른다.

## 구현 순서와 마일스톤

| 마일스톤 | 결과 | 이슈 |
| --- | --- | --- |
| M1 | 기존 빌드·공통 코드 축소 | #1, #2 |
| M2 | 안건 생성→QR 공유→닉네임 참가를 서버·화면까지 연결 | #3, #4, #6, #12, #13, #15 |
| M3 | 아이디어 1개 저장·익명 클릭 평가·수동 단계 전환 | #7, #8, #10, #16 |
| M4 | 진행자 관리 영역·결과·채택 | #9, #17 |
| M5 | 제외·통합 작업의 이력 보관(종료) | #5, #14 |
| M6 | 핵심 규칙 검증·여러 브라우저 연동·실행 문서 | #11, #18 |
| M7 | 개발 완료 후 PostgreSQL 전환·DB 확인 | #19 |

M3에서 실제 평가를 확인할 수 있도록 수동 단계 전환 #10을 함께 구현한다. M4에서는 진행자 관리 영역과 결과·채택 화면을 연결한다. 각 마일스톤에서 서버와 화면을 연결해 해당 단계의 실제 흐름을 확인한다.

### 이슈의 완료 범위와 검증 책임

각 이슈는 자신이 맡은 기능과 제한을 구현·검증하면 완료할 수 있다. 선행 기능은 사용하되 후속 API·화면의 완성을 완료 조건으로 삼지 않는다. 후속 연결은 이슈의 관계와 이후 방향에 기록한다. 필요한 참가 기록·안건 상태·아이디어·평가는 검증용으로 준비할 수 있으며 검증만을 위해 후속 기능을 먼저 구현하지 않는다.

- #3은 키 생성·안건별 참가자 식별·진행자 여부 구분을 담당한다. 생성·참가 시 실제 키 부여는 #4·#6, 브라우저 보관·헤더 전송은 #13이 담당한다. 실제 진행자 전용 API의 비진행자 거부는 해당 API 이슈에서 확인한다.
- #6·#7·#8은 각각 참가·작성·평가 API의 단계 제한을 확인한다. #10은 전환 권한·현재 단계·전환 조건과 상태 저장을 확인한다. 실제 전환 후 다른 API의 허용·거부가 연결되는지는 M3에서 함께 확인한다.
- 서버 이슈의 완료 기준은 API 응답·저장·제한에 둔다. 입력 유지·클릭 저장·오류 문구 등 화면 동작은 화면 이슈에서 확인한다. 여러 브라우저의 생성·공유·참가와 단계별 흐름은 해당 마일스톤에서 확인한다.
- M2의 #12는 안건 진입·닉네임 참가 폼·실패 안내·재접속과 현재 단계 안내를 담당한다. #13은 M2의 호출·키·공유 주소·QR 처리와 첫 연결에 필요한 API 주소/CORS 설정, #15는 생성·공유 화면을 담당한다. #12·#13은 이 범위로 완료하고 이후 호출·화면 연결은 #16·#17에서 확장한다.
- M3의 #16은 작성·평가 화면과 최소 전환 조작·안건 상태 갱신을 담당한다. 갱신 방식·간격은 이때 확인한다. RESULT에서는 입력을 종료하고 결과 단계임을 안내하며 결과 분포·채택 화면은 요구하지 않는다. M4의 #17은 전체 관리·결과·채택 화면을 연결하고 갱신을 참가자 목록·결과·채택으로 확장한다.
- M6의 #11·#18은 기존 기능별 검증과 마일스톤 확인 결과를 재사용해 전체 흐름의 연결·누락을 확인하고 보완한다. #18은 최초 연동 설정을 새로 만드는 단계가 아니라 최종 환경에서 설정을 재확인하고 실행 문서를 정리하는 단계다. PostgreSQL 전환과 DB 차이 검증은 마지막 #19에서 수행한다.

## 개발 환경과 현행 코드

개발 중 H2 local(create-drop)를 사용한다. 서버 재시작 시 데이터는 사라진다. 개발 완료 마지막에 PostgreSQL로 전환하고 연결·스키마·제약·핵심 흐름을 확인한다.

Security·JWT·OpenAPI 생성기 설정은 #1에서, 공통 오류코드·BusinessException·BaseEntity와 JPA 시간 자동 기록은 #2에서 제거했다. 공통 오류 응답은 HTTP 상태와 `{message}`만 제공한다.

개정 전 개요 PDF는 `archive/moasseugi-overview-before-simplification.pdf`에 보관한다. 현재 요구사항은 이 문서와 API·DB·프론트 설계를 따른다.
